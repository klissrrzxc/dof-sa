# Архитектура и границы доверия

Браузер → Next.js SSR / Server Actions → Supabase Auth + PostgreSQL. Браузер не содержит Supabase-клиента, service-role ключа или доверенной роли из metadata. Все пользовательские запросы БД идут с пользовательской сессией и RLS. Service role используется только на сервере для API приглашения, после `requireAccess('users.manage')`; он не используется для чтения реестров.

Проверка в proxy обновляет cookies и перенаправляет анонимных посетителей. Layout и каждый обработчик повторно проверяют пользователя через `getUser`, действующий профиль, организацию и MFA. Proxy не является единственной границей защиты. `forbidden()` возвращает 403. Серверные компоненты не кэшируют персональные данные; служебный layout динамический.

Таблицы публичной схемы защищены RLS, прямые записи отозваны. Публичные RPC являются `SECURITY INVOKER` оболочками. Привилегированные реализации находятся в неэкспонируемой схеме `private`, проверяют `auth.uid()`, текущий профиль, полномочия и AAL, используют пустой `search_path`, явные схемы и ограниченные EXECUTE grants. Нет операций по metadata клиента. Назначение роли и аудит записываются одной транзакцией. Самоназначение запрещено. Администратор не получает финансовые разрешения автоматически.

Обязательное MFA: все повышенные роли и все пользователи с дополнительными permission grants. Профиль и организация перечитываются на каждом запросе: блокировка действует и на старый access token. Отзыв Auth-сессий — отдельное действие владельца, не утверждается как выполненное. Таблицы аудита не имеют клиентских UPDATE/DELETE/INSERT grants.

Storage bucket приватный, PDF/PNG/JPEG до 10 MiB; доступ к объектам по умолчанию запрещён. Загрузка/скачивание появятся только вместе с проверенной моделью связи файла и дела. В первой поставке нет небезопасной универсальной выдачи signed URL.

Next Server Actions применяют встроенную проверку Origin/Host. APP_ORIGIN задаётся владельцем, не берётся из Host запроса для писем. Rate limits входа и OTP задаются в Auth. До production нужны также ограничения входящих запросов и инвайтов на Vercel; in-memory ограничитель не используется, поскольку не защищает несколько инстансов.

Суммы в будущих финансовых таблицах — BIGINT, в TypeScript — десятичные строки/BigInt; часы в БД — timestamptz UTC. RP timezone пока не задана, выбирать её из системной локали нельзя. Публичного реестра, регистрации, метрик, демонстрационных сессий нет.
