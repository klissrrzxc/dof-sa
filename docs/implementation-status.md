## Реализовано

- Доступ через публичную заявку /register с собственным паролем и обязательным одобрением администратора; вход по Static ID или legacy email, MFA отключена по указанию владельца; серверная проверка действующего профиля и организации. Пользователь подтвердил успешный вход; затем авторизованная сессия проверена при чтении страниц.
- Шесть модулей: обзор задач и казны; реестр и карточки дел; казначейство; архив документов; публичные сводки; администрирование.
- Новые внутренние формы FMS для финансирования и закупок с обязательными реквизитами актов. Черновик, версии, подача, уточнения/повторная подача, рассмотрение, частичное согласование суммы, отказ и отзыв до несовместимых исполненных операций. Фильтры типа/статуса/ведомства/даты/суммы/назначения, страницы по 50 строк.
- Закупочные позиции с целочисленной арифметикой и проверкой итоговой суммы, сведениями о поставщике, полномочиях, ответственном лице и заинтересованности. Для подачи закупки нужен загруженный документ.
- Приватные PDF/PNG/JPEG до 10 MiB, проверка MIME и сигнатуры на сервере, Storage RLS по делу, проверка факта загрузки. Скачивание по проверенному маршруту с signed URL на 60 секунд и аудитом доступа.
- Решение, резерв MOF-COM, ордер MOF-CO и фактический расход MOF-EXP разделены. Резерв и лимит проверяются транзакционно. Ордер не меняет баланс. Исполнение требует уникального подтверждения и доказательства реального игрового перевода. Нет автоматических банковских переводов.
- Первоначальный остаток, включая подтверждённый нулевой, вводится по основанию. До него казна обозначена как неинициализированная. Доход учитывается только после подтверждения и создаёт отдельное закрытое дело INCOME_RECORD, без расходного согласования.
- Аннулирование неисполненного ордера, выпуск нового ордера, освобождение неисполненного резерва. Коррекции доходов и возврат неиспользованного остатка — новые компенсирующие записи; исходные документы/решения/проводки защищены от UPDATE/DELETE.
- Отчёт о целевом использовании: доказательства, возврат на доработку, принятие и закрытие дела после исполнения/урегулирования остатка.
- Документы с последовательностями по типу/году и immutable версиями; печатная HTML-карточка с сохранением PDF через печать браузера.
- BBCode из подтверждённых проводок: начальный баланс, доходы, расходы, корректировки, итог, резервы, статьи и ведомства; без частных счетов/комментариев. Проект → проверка → утверждение → выгрузка. SHA-256 и запись утверждения, запрет утверждения устаревшего среза, ручная форумная публикация.
- Организации/реквизиты, периоды, версионный классификатор с нормативным источником/ручной проверкой, назначения и отдельные permission grants, отзыв и блокировка. Самоназначение запрещено. CSV аудита/казначейства с защитой от формул.
- Реальная Edge Function staff-invite развёрнута. Она проверяет getUser и полномочия через БД, затем использует штатный служебный ключ внутри Supabase. Next.js не требует service-role key. Письма реальным сотрудникам в ходе разработки не отправлялись.

## Проверено

- TypeScript strict, ESLint, production build.
- 48 unit/SQL теста: RLS/IDOR, роли и парольный доступ, финансовые состояния, идемпотентность, повтор запроса после отзыва полномочий, сверхрезерв, точность BIGINT, возвраты/коррекции, закупочные реквизиты/вложения, аннулирование ордера, отчётность, нулевой начальный остаток, CSV.
- Playwright проверяет анонимный доступ к служебным маршрутам, экспортам и файлам, страницу входа, обработку истёкшего приглашения, восстановление, отсутствие обхода callback и мобильный вход. Итог последнего прогона указан в сообщении поставки/CI.
- workflow-smoke.sql прошёл на реальном PostgreSQL Supabase с ROLLBACK: полный финансовый цикл и BBCode, без сохранения тестовых пользователей, денег или дел.
- Реальные анонимные REST SELECT на 26 таблиц — 401; my_access / perform_operation / case_file — 401; Storage не раскрывает объекты; staff-invite без сессии — 401. Публичный signup отключён.
- В пользовательской сессии проверены загрузка казначейства, архива, отчётности, администрирования и все шесть пунктов меню. Мутации реальных финансовых данных через браузер не выполнялись.
- Security Advisor не обнаружил замечаний к таблицам/функциям/RLS. Отдельное WARN: в облачном Auth выключена проверка скомпрометированных паролей; владелец должен включить её, если она доступна на тарифе: [настройка защиты паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

## Существенные ограничения перед production

- Реальная доставка приглашения новому сотруднику через Edge Function и загрузка/скачивание реальных байтов Storage ещё не пройдены end-to-end. SQL проверяет политики и завершение метаданных, но не заменяет такую проверку.
- Тест сверхрезерва выполнен в PGlite и транзакционные проверки — в облачном PostgreSQL. Нагрузочный тест нескольких независимых PostgreSQL-сессий не выполнен. MVP сериализует все операционные RPC единым pg_advisory_xact_lock; это безопасный простой вариант для малого штата, с ограниченной пропускной способностью.
- Частичные платежи по одному ордеру отключены. Один подтверждённый возврат остатка на расходную запись; коррекции закрытых дел/периодов блокируются. Исправление принятого публичного отчёта — новая редакция.
- Незарегистрированные черновики сохраняются; отдельного удаления черновика/уборки незавершённых файлов пока нет. Незавершённые файлы не выдаются для скачивания.
- Блокировка профиля немедленно закрывает RLS/SSR; глобальный отзыв Auth-сессий выполняется владельцем через Dashboard. MFA-факторы владельца удалены по его явному запросу; пароль сохранён.
- Для штатной почты нужен production SMTP и настройка лимитов Auth. База ограничивает успешные операционные RPC до 60 в минуту на пользователя; перед публичным хостингом настроить Vercel Firewall для входа/восстановления/приглашений.
- RP timezone пока не утверждён: в интерфейсе явно указан UTC.
- Начальные остатки, лимиты, реальные классификаторы и реквизиты не выдумывались. Владельцу необходимо заполнить их по документам. Данные финансовых тестов полностью откатывались.
- Vercel, production-домен, реальные backup/restore и полная производственная приёмка ещё не выполнены. Система не объявляется прошедшей весь production release checklist.
