# Публикация на GitHub Pages

Основной адрес: https://klissrrzxc.github.io/dof-sa/ . GitHub Pages обслуживает статические HTML/CSS/JS; маршруты приложения имеют вид `#/app/cases`. Серверные операции выполняет Supabase, Node/Next сервер для публикации не нужен. Vercel не используется.

## Устройство

- `web-client/` — браузерная точка входа, маршрутизация, адаптер авторизации и действий. Общие формы и страницы в `src/` используются обоими вариантами сборки. Асинхронные компоненты загрузки данных разрешаются браузерным адаптером до React-рендера; они содержат только запросы с пользовательскими правами.
- `vite.config.ts` явно заменяет Next Server Actions браузерными адаптерами. Никакие служебные ключи в эту сборку не входят. `build:pages` создаёт `dist-pages`.
- Все изменения финансов проходят существующие Postgres RPC с актуальными проверками роли, статуса профиля, лимита, остатка и идемпотентности. Браузер не является источником полномочий. Публичные Auth metadata не используются как роли.
- `access-request` принимает заявку; `case-file-upload` самостоятельно проверяет JWT через Auth, тип/сигнатуру/размер файла и вызывает RPC/Storage от имени пользователя. Service-role нужен только внутри управляемой функции регистрации, не в браузере.
- Для браузерных Edge-вызовов настроен CORS с точным origin `https://klissrrzxc.github.io`; пути GitHub Pages не являются отдельными origin. Локальные origin разрешены для разработки. CORS не заменяет авторизацию.
- В статической версии сессия Supabase хранится в браузере, а не в HttpOnly cookie. Токены не попадают в репозиторий и в статические HTML. React экранирует данные, CSP ограничивает скрипты и сетевые подключения. Не вставлять пользовательский HTML через dangerouslySetInnerHTML и не добавлять сторонние скрипты.
- Pages не позволяет задавать все серверные заголовки из Next.js. В HTML заданы CSP, noindex и no-referrer. Приватность данных обеспечивается Auth/RLS, а не сокрытием адреса сайта.

## Автопубликация

В репозитории включён Pages build_type=workflow. `.github/workflows/pages.yml` при push в `codex/fms-foundation` устанавливает зависимости, проверяет TypeScript/ESLint/SQL-тесты, собирает Pages, запускает браузерные проверки и публикует артефакт. Передача версии выполняется через actions/deploy-pages и OIDC.

Репозиторные Actions Variables `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` содержат публичную клиентскую конфигурацию. Не добавлять туда service-role или секретный ключ. Для смены Supabase проекта обновить эти переменные и точный CSP connect-src, затем пересобрать сайт. Для локального preview используются NEXT_PUBLIC-переменные из игнорируемого `.env.local`.

Для восстановления старой email-учётной записи в Supabase Auth Site URL и redirect allowlist должны включать точный адрес Pages. Новая регистрация по Static ID не отправляет письма; потерянный пароль требует помощи владельца Auth после проверки личности. Пароль существующего Thomas Schoufield не изменён; вход остаётся по прежнему email и паролю.

## Каталог и обучение

Миграция owner_budget_catalog добавляет 18 расходов и 6 доходов из сообщения владельца 12.11.2026. Источник указан честно: каталог владельца, а не вымышленная внешняя публикация. Суммы, лимиты и периоды не создаются. Выбор расходной статьи подставляет код/название и показывает описание и документы-основания. Старые редакции не перезаписываются. Последняя непроверенная редакция не заменяется автоматически старой проверенной.

Разделы «Помощь и инструкции», «Каталог статей», быстрые действия на обзоре, следующий шаг по статусу дела и пояснения под полями помогают пользователям. Все примеры вымышленные, значения не записываются вместо реальных сведений.

## Проверки и ограничения

50 модульных/SQL-тестов и 8 браузерных проверок статической версии. На реальном Supabase проверены регистрация/ожидание, одобрение, создание черновика, выбор всех 24 статей, приватная загрузка PNG и чтение административного, казначейского и отчётного разделов. Тестовый черновик, организация, роли и файл удалены. Тестовая Auth-запись заблокирована и сохранена только как ссылка из неизменяемого аудита; активного профиля у неё нет. Денег, лимитов и периодов тест не создавал.

Остаются общие ограничения из implementation-status.md: ручные игровые переводы и публикация на форуме, реальная нормативная сверка, настройка реквизитов/периодов/лимитов владельцем и проверка восстановления резервных копий.
